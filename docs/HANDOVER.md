## 10. Operational gotchas
- Never use `pkill -f` with patterns that match your own shell (exit 144); use `ps -eo pid,args | grep "[x]..." | awk '{print $1}' | xargs kill`, and do not put the pattern text in the same command.
- Local Postgres: `rm -f /tmp/pgdata-ph/postmaster.pid; su postgres -c '/usr/lib/postgresql/16/bin/pg_ctl -D /tmp/pgdata-ph -o "-k /tmp -p 55432" -l /tmp/pgdata-ph/server.log start'`. Backend tests: `TEST_DATABASE_URL="postgresql://postgres@/ph_test?host=/tmp&port=55432" REQUIRE_DB=1 python3 -m pytest -q tests`.
- Local e2e: build the frontend, run the backend with `PH_OFFLINE_FIXTURES=1` and a Postgres `DATABASE_URL` (seed with `python seed_demo_scans.py`), then `npx playwright test`. Four tests can fail under heavy parallel load and pass alone; check before changing anything.
- MCP tools (GitHub, Railway) sometimes disconnect and reconnect; reload them with ToolSearch. Large GitHub job logs are saved to a file: slice with Python.
- After a squash merge into `v2`, branch the next change fresh from `origin/v2`.
